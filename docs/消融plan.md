# 3RScan 消融计划

整理日期：2026-10-16。状态：实验设计，尚未宣称新增消融已经完成。

依据《CVPR论文创新点与模块组织_通俗版》与当前源码。当前系统为共享全局 **2.5 cm TSDF + IGSubmap + Feng + ObsRefine**；没有局部 TSDF、多分辨率或运动轨迹估计。Feng 是本系统的变化检测与删除机制名称。

## 1. 要回答的三个问题

1. **删谁：**历史观测对应的实例合并、重排后，能否找到正确的当前实例？
2. **何时删：**深度/RGB 矛盾与独立观测确认，能否区分真实变化、遮挡和单帧噪声？
3. **怎样删：**整实例退役与共享几何保护，能否清理旧物体，同时保留仍然存在的物体？

ObsRefine 单独回答最终点的实例归属是否更准确。它属于导出细化，不把它解释为几何删除或 RGB 变化检测。

## 2. 主实验：9 个配置

每个变体必须与 Full 使用完全相同的输入及评估域。表中“保持其他项”包括 2.5 cm 分辨率、mask、帧序列、位姿、关联与评价阈值。

| ID | 配置 | 只改变什么 | 回答什么 | 实现状态 |
|---|---|---|---|---|
| B | 原始 Baseline | 固定原始提交 507dfd5 | 总体参照；不能当作单个模块的消融 | 已有 110 对结果；独立原始 checkout |
| F0 | IGSubmap + ObsRefine，Feng off | 关闭显式变化检测/删除 | 同一实例系统中，Feng 的增量作用 | `--correction off` |
| O0 | IGSubmap + Feng，ObsRefine off | 不做最终归属细化 | AP 增益是否依赖 ObsRefine | `--observation-refine off` |
| Full | IGSubmap + Feng + ObsRefine | 完整当前方案 | 所有消融的共同参照 | 已有 110 对结果 |
| RGB0 | Full，仅深度 | detector config 的 `rgb_enabled=false` | RGB 对深度相近变化的作用 | 配置已有；新配置尚需验证 |
| T1 | Full，单次有效观测确认 | `confirm_observations=1`，保留单帧可靠性筛选 | 累计确认能否减少误判 | 配置已有；新配置尚需验证 |
| H0 | Full，无历史后继解析 | 保留稳定身份；移除历史来源到合并后实例的解析 | 历史来源链是否必要 | 需要新增受控实现 |
| L | Full，局部清理 | 相同确认事件，仅清理局部矛盾几何，不执行整实例退役 | 整实例语义更新是否优于局部擦除 | 需要新增受控实现 |
| S0 | Full，无共享几何保护 | 取消目标几何与其他活跃实例重叠部分的保护 | 共享保护能否减少误伤 | 需要新增受控实现 |

共 9 个配置，其中 B/Full 已有结果，原则上新增 7 个配置。110 对 × 7 = **770 次新增配对流运行**，不是新增 770 个不同场景。若输入、核心源码或协议改变，旧 B/Full 不能直接复用。先做小规模实现验证再全量运行。

### 必须控制的实现细节

- **H0 不能用旧数组槽位直接删对象。**槽位重排会变成实现错误。应冻结稳定 ID；ID 不再对应活跃实例时明确跳过，并记录无法解析率。与 Full 比较解析成功率、删错/漏删和最终 AP。
- **L 必须继续维护基础缓存、索引和几何一致性。**不能通过故意留下悬空引用制造差距。所有变体的实际几何擦除都走同一记录接口，保留 GAP 需要的完整 incident-edge 证据。
- **S0 只去掉几何共享保护。**仍同步更新正常状态，记录受影响的其他活跃实例；不能混入失效缓存或异常退出。
- **T1 同时改变证据数量。**它不能单独证明“独立视角”有效；补充一个确认数量仍为 2、只去掉视角/时间间隔约束的实验，才能隔离独立性贡献。评价域中的两次自由空间观测规则不随算法消融改变。
- **O0 不一定必须重建。**只有确认保留的未细化导出或 checkpoint 与当前运行共享完全相同几何和在线状态后，才可复用并重新导出；没有证据就正常重跑。不能把已经细化的输出当作 O0。
- **B 与 F0 不只差 Feng。**B→F0 包含实例组织与 ObsRefine 等变化；F0→Full 才是受控的 Feng 对照。

## 3. 补充消融与优先级

优先顺序：先 Full/F0/O0 验证主增益，再 L/H0/S0 证明实例维护链条，最后 RGB0/T1 解释检测机制。这里是论文解释优先级，不意味着根据分数挑选保留变体。

预算允许时增加：

| 补充对照 | 目的 |
|---|---|
| IGSubmap，Feng off、ObsRefine off | 补齐 Feng × ObsRefine 的 2×2 对照，检查交互效应 |
| `baseline_components` 与 `disjoint_pairs`，其他模块相同 | 隔离实例关联方式；它不是“原始 Baseline” |
| 确认数相同，仅取消独立视角门槛 | 隔离独立观测条件，而非单纯多看一次 |
| 深度、确认数等小范围敏感性 | 检查结论是否只在一个阈值成立；在开发集定范围 |
| 显式检测开启的无变化/静态组 | 检验没有目标时是否误删；不能用 Feng off 的静态实验替代 |

等价加速仅报告时间/显存，不作为主要精度创新；当前论文不加入多分辨率消融。

## 4. 场景选择与统计

主表使用固定的 **110 个 reference→rescan 配对、47 个 reference 场景组**，不按 AP、GAP、D 或删除动作数量筛选。固定清单在 `tools/current_system/validation_pairs.json`。

先在预先固定的小集合上验证程序、日志和指标，再一次性跑完整清单。开发用过的配对要披露；同一 reference 的多个 rescan 不应当作完全独立样本。误差条建议以 47 个 reference 组做成组配对 bootstrap，每次对所有方法抽相同的组；pooled AP 每次重新合并该次抽样的匹配记录，并为重复抽取的组重命名匹配 ID。

“每组仅保留删除或移动物体最多的一次重扫描”可以作为预先定义的附加子集；变化数只来自标注。**之前按我们 GAP-v3 较高来打破并列的 47 对结果属于事后选择分析**，不能用作消融主表或独立证明。正式固定子集并列时用 UUID/原清单顺序等与分数无关的规则。

AP=0、D=0、没有显式删除动作、没有可评价删除目标都不自动排除。AP=0 是有效失败表现；无目标场景能检验误删。数值未定义与零不同：没有有效 GT 时 AP=null；没有动作时删除 precision=null；没有删除目标时 recall=null，单独报告有效样本数。运行失败保留日志和缺失清单，不只统计成功的方法。

## 5. 评价表怎么做

每一行对应一个配置，建议分成分割、删除和代价三组列：

| 组别 | 指标 | 用途 |
|---|---|---|
| 最终分割 | pooled AP/AP50/AP25 | 主分割结论；从所有匹配记录合并 PR，不能平均场景 AP 替代 |
| 场景统计 | mean AP/AP50/AP25 | 与逐场景 D、GAP 相互核对，明确与 pooled 区分 |
| 显式删除 | D、precision、recall、TP/FP/FN、有效场景数 | 判断清理收益和错误来源 |
| 综合辅助 | mean GAP-v3/GAP50/GAP25 | 展示分割与动作审计的复合结果 |
| 安全性补充 | 未变化表面损失、共享区域损失、无目标组误删 | 防止只看“删得多” |
| 代价 | 主循环/总/准备耗时、进程显存峰值、删除次数/延迟 | 衡量维护开销；显存归属不明为 null |

当前 D 是空间表面原子的动作审计，不是实例 IoU 阈值分数。因此：

```text
D = TP / (TP + FP + FN)
GAP-v3 = AP + (1 - AP) D
GAP50  = AP50 + (1 - AP50) D
GAP25  = AP25 + (1 - AP25) D
```

所有值先用 0–1 计算，展示时乘 100。**GAP25/50 共用同一个 D；目前不存在两个独立的 D25/D50。**不要只改列名制造两个新指标。若未来定义实例级 D@IoU，需要独立协议、匹配和验证，不与本次 D 混用。

GAP 是自定义辅助分数，不是官方 AP，也不能独立证明整体系统更好。例如 AP=0、D=1 时 GAP=1，会掩盖最终分割完全失败。应同时报告 AP、D 和误删，给出变化来自哪一项。

Baseline 的 D=0 表示没有本协议审计的显式擦除动作，不等于自然 TSDF 更新完全不能清理旧几何。为了公平比较“最终有没有残影”，建议另加**方法无关的结果指标**：先固定可观测 GT 旧表面，再检查最终残留和仍存在表面的损失，并报告边界时刻初始重建覆盖率。未重建的旧物体不能直接计成成功删除。这个补充指标当前尚未实现。

## 6. 可复现要求与交付

固定并保存：源码提交与核心文件 SHA、每个变体配置 SHA、原始数据及重投影输入摘要、两法共享 masks、帧 ID/stride、随机种子 27、相机坐标与米/毫米约定、GT 标签顺序、共享 GAP domain SHA、硬件与依赖版本。

每个变体独立输出目录，保留 final.ply、ckpt_final.npz、AP 匹配记录、GAP domain、correction/summary.json、擦除 archive 及 `.evidence.npz`、日志、计时和失败重试记录。不能通过重跑覆盖已经成功的结果。原始 AP、旧筛选口径和全实例口径分开存放。

报告应包含全量主表、逐场景配对差值、按 removed/moved/无目标的分层、失效候选到实例后继的解析日志，以及少量预先选定的时序可视化。removed/moved 的诊断 FP 可能共享，不能直接相加当作总 FP。

执行入口和精确定义见 [CURRENT_SYSTEM.md](https://github.com/ElainaX/OnlineSegmentationBaseline/blob/release/current-system-ap-gap-20261016/docs/CURRENT_SYSTEM.md)。本文件本身不授权启动新的实验或修改正在运行的 ScanNet/3RScan 作业。
