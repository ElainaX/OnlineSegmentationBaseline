## 接入的内容

新增 `submap_disjoint/change_frontend.py`：

- 融合前 raycast 全部已分配历史块；可选预热，保留旧近处表面查询。
- 收集深度、颜色、插值邻居与权重。默认插值系数覆盖至少 99%、表面权重至少 3。
- 世界表面参考点也按权重 3 提取，避免分母包含低置信度表面，而这些点永远无法投票。
- 当前/历史深度边缘、孔洞与实例归属边界排除。
- 默认深度容差改用本机前端的 `0.08 + 0.01 * max(current, reference)` 米。
- 深度一致时做 RGB 偏移补偿、Lab 色差、中位数/MAD 自适应阈值。
- 至少 80 个可靠像素用于 RGB 阈值估计，不足时不产生颜色证据。
- 像素到实例的归属不使用 raw mask 多数票。`owners_from_stencil` 接受体素到当前实例集合的回调；
  同实例的多次观测只算一个 owner，多实例同时参与则为歧义。
- 独立子图入口使用渲染深度组合 owner：不同身份在近似同深度重叠时排除；
  已显式关联同一长期身份的多个片段共用 owner，几何仍独立。
  一个片段同时显式属于多个身份时报错，不静默选择身份。
- 候选要通过像素级和参考点级数量/矛盾比例检查。
- 全局矛盾比例超过 75% 暂停本次证据更新，避免整帧异常直接导致状态更改。
- 图像和片段统计区分 depth 与 RGB，记录跳过/候选拒绝原因。

不照搬之处：

1. RGB 色差不转成 FREE。深度证据与外观证据从数据结构到状态决策分开。
2. 不直接执行本机“累计 20% 区域、2 次观测 -> would_remove”的规则。
   候选筛选较宽松，几何停用仍沿用现有严格表面共识；所以不是与本机逐位等价的实现。
3. 实例成熟度使用片段的独立帧观测记录数，默认 5，而不是 baseline 的合并 mask 权重 5。
   两个数物理含义不同，不能宣称等价。后续主循环适配可另行提供原始身份置信度。
4. RGB 输入明确区分 uint8 [0,255] 与 float [0,1]；不靠亮度百分位猜测量纲，
   避免把几乎全黑的 uint8 图误作归一化颜色。
5. 前端颜色关闭时跳过颜色渲染和 Lab/MAD 处理，保留有效深度路径。

## 与生命周期的衔接

顺序：

`旧几何渲染 -> 质量/归属过滤 -> 像素候选 -> 固定表面证据 -> 生命周期决策 -> 临时几何融合`

旧片段提前封存；新片段始终写到 pending，不参与正式地图发布。
参考片段若太小或观测不足，批量注册会保留它的历史几何，但记录 `reference_skips`，
不把它用作变化证据，不让一个小实例中断整条序列。
手动注册单个不合格参考仍显式报 `ReferenceNotReady`，便于调用方处理。

临时片段需同时满足生命周期和前端成熟条件才取固定表面样本、停止增长。
默认原 3 次观测与前端 5 次观测取最大值 5，修复了“3 帧封存、永远达不到 5 帧门槛”的冲突。

候选一旦满足筛选，其后可靠的固定表面证据进入原有滑动视角窗口。
真正停用仍需要同一表面单元至少 3 个视角确认 FREE、80% 同向有效票，
并且确认单元至少 20 个、覆盖完整参考采样的 60%。RGB 不参与这个 FREE 计数。

- 只有 RGB 变化：可以 stable/accepted -> suspect；不因此 retired。
- 有足够深度自由空间证据：可以 retired。
- 当前深度更近：occluded；不能证明旧表面消失。
- 颜色仍明显矛盾：不凭几何支持自动批准 pending 或恢复旧片段为稳定。
- 新物体是否接受、旧物体是否停用仍分别判断。
- 停用后保留旧几何，继续支持后续恢复。

interval 默认 10，按原始 frame ID 对齐。只有实际审计步推进证据窗口年龄，
跳过的原始帧不消耗 64 个审计步预算。非审计帧可以收集未封存的 pending 观测。
前端质量保护跳过某次审计时不会产生状态票。
该版颜色警告是当前审计帧的额外条件，没有新增独立的长期外观身份推理模块。

## 检查点与关闭开关

检查点升级为格式 2，保存 frontend 配置、候选状态统计、参考排除原因和原有逐点视角历史。
兼容格式 1；读旧检查点时 frontend 默认关闭，不暗中改变旧实验行为。
恢复检查点不能通过配置参数覆盖已有设置；公平对照请使用同样输入新建一次运行。

旧控制路径保持默认关闭前端。新增配置：

- `config/change_frontend_control.json`：前端关闭，原深度检测路径。
- `config/change_frontend_depth.json`：质量筛选、归属筛选及候选生成，只用深度。
- `config/change_frontend_rgb.json`：与上一项相同，再加 RGB。

后两项只改变 RGB 开关，便于单独评估颜色证据。第一项与后两项同时存在阈值、质量筛选
和候选入口差异，不能将第一项到第三项的变化全部归因于 RGB。

有卡后使用同一套参考/实时包：

```bash
python run_change_lifecycle.py --manifest packets/frames.jsonl \
  --config config/change_frontend_rgb.json --output /path/to/new/output
```

NPZ/JSONL 输入格式沿用 `docs/change_lifecycle.md`：reference 包先提供已关联片段 mask，
live 包提供当前 provisional fragment mask，深度为米、K 与 RGB-D 对齐、位姿为 T_world_camera。
新配置要有至少 5 次参考观测，帧采样应与 interval 对齐。
这些配置不是 baseline `main.py -c` 的 YAML，不能直接传给 main.py。

## 当前验证边界

只执行 CPU 单元/集成检查和语法检查，命令明确设置 `CUDA_VISIBLE_DEVICES=`。
`test_change_frontend_cpu.py` 有 25 项检查，包括：

- RGB-only 候选不会停用几何，depth 候选可以驱动原可逆后端；
- 遮挡、中空插值、低权重、owner 歧义、全局异常的处理；
- 同实例多 raw mask 不淹没其他 owner，显式同身份片段不制造假歧义；
- 全局曝光偏移与局部颜色变化，暗 uint8、NaN、校准样本不足；
- 颜色关闭时不执行颜色处理；
- 采样跳帧、5 帧成熟度、低质量参考跳过、旧控制路径；
- 已有候选也必须满足单帧参考点数量要求，私有几何不能穿过归属歧义区域投票；
- 格式 2 保存恢复后判断一致，格式 1 默认关闭新前端。

控制器测试使用固定 NumPy 渲染结果和假体素存储，只验证代码路径与证据决策。
它们不代表真实 GPU raycast、TSDF 融合或真实数据检测准确率已经通过。
新 `render_quality` 的 Open3D GPU 权重索引、颜色量纲、预热和性能仍需有卡后验证。
没有运行 ScanNet/3RScan 重建、AP、速度或显存实验。
